## 二、其他用户如何接入大模型（你最关心的成本问题）

StudyBuddy 内置 **两条模型通道 + 一个演示模式**，可在「设置 → 大模型通道」一键切换：

| 通道 | 接入方式 | 费用由谁承担 | 适用人群 |
|---|---|---|---|
| **① WorkBuddy 账号通道** | 点「使用 WorkBuddy 登录」（微信 / 手机号 / 邮箱 / SSO），登录后调用**自动计入该访客自己的 WorkBuddy 积分** | **调用者本人**（作者 0 成本） | 零配置体验者、评委 |
| **② 我自己的 API Key** | 填 Base URL / Key / 模型名，兼容所有 OpenAI 协议服务（DeepSeek、Kimi、智谱、通义、本地 Ollama…） | **用户自己**（作者 0 成本） | 有 Key 的开发者 |
| **③ 演示模式**（默认） | 内置离线样例响应，不调用任何模型 | **0** | 完全零门槛体验全流程 |

**结论：作者 0 成本，且已无法被消耗。** 原先的「公共体验通道」（作者挂公共 Key 给访客白嫖）**已彻底下线**。

### 为什么「未登录时」必须禁用通道 —— 一个真实的坑

SDK 的每次请求只带两个头：

```js
headers.set('x-wb-webapp-access-key', publishableKey)   // ① 只标明"是哪个应用"，本身不带权限
if (!headers.has('Authorization')) {
  const token = await getSessionToken()                  // ② 访客会话令牌
  if (token) headers.set('Authorization', `Bearer ${token}`)
}
```

- **访客未登录** → ② 不存在 → 服务端识别不出调用者 → 计费落到**应用创建者（你）**头上
- **访客已登录** → 带上 Bearer 令牌 → 服务端识别出该账号 → 计费到**访客自己**头上

所以「打开链接就能白嫖模型」这件事，代价其实是**作者的钱**。本作品的处理方式是：
**未登录时 WorkBuddy 通道直接禁用并给出明确提示，登录后才可用**；同时把当前归属状态明示在首页顶栏、右侧「学习台 → 账户与计费」卡片、侧栏底部入口和设置页四处。

> 安全兜底：服务端还会做 **Origin 精确匹配** + 分享码校验，别人抄走 `publishableKey` 也无法当公共代理刷。

### 怎么查真实消耗

**SDK 不暴露用量/配额/计费接口**（官方文档明确说明），要去 WorkBuddy 控制台「设置—数据管理—应用」看。

## 三、评委 3 分钟演示动线（建议照此录屏）

1. **0:00–0:20｜开场**
   打开链接 → 落地即看到「示例材料 · 注意力机制与 Transformer」（已预置，任何人都能立刻体验，不需要先传文件）。
   顶栏明示「未登录 · 不消耗任何人的积分」，右上角一键「使用 WorkBuddy 登录」→ 跳转官方授权页（微信扫码 / 手机号 / 邮箱 / SSO）。

2. **0:20–1:10｜核心演示：沉浸式选区阅读**
   进入「沉浸式阅读」→ 左侧是真实渲染的文档，**用鼠标选中公式下方的两句话** → 右上浮出工具条：
   - 点「解释这段」→ AI 立刻针对**这一句**展开，而不是泛泛讲整章
   - 点「举个例子」→ 给出带数值的具体算例
   - 点「可视化」→ 直接生成 Mermaid 结构图
   - 点「记入图谱」→ 该知识点立刻出现在知识图谱里
   > **这一步是全场最抓人的动作，务必录进去。**

3. **1:10–1:50｜演示「会长大」的记忆系统**
   - 切「知识图谱」：展示自动生长的节点与前置/相关关系，点节点可直接发起追问
   - 切「记忆库」：L1 原始轨迹 / L2 事实摘要 / L3 跨面综合三层，**每条结论都能溯源**，且可手工修正
   - 切「题库与练习」：AI 自动出题 → 提交自动批改 → 错题自动进错题本

4. **1:50–2:30｜演示「星空成长」**
   选资料 → 点「水平诊断」→ AI 出 5~8 道诊断题 → 作答得分 → 一键「自动拆分知识模块」→ 逐模块「消化」→ 「检验」→ 得分自动更新掌握度与艾宾浩斯复习排期（1/2/4/7/15/30/60 天）。

5. **2:30–3:00｜收尾：三个亮点**
   - **四套主题**：经典白 / 深蓝科技 / 青蓝清新 / 皮卡丘黄（即时切换，皮卡丘做了淡化水印处理）
   - **真实文献**：文献调研页接 Semantic Scholar + OpenAlex（均支持 CORS、免费无需 Key，覆盖 arXiv），点「让 AI 精读」直接进入讲解
   - **数据不出本机**：所有资料、笔记、图谱、题库、记忆存在浏览器 IndexedDB，支持一键导出/导入备份

## 四、对标 DeepTutor：超越点与借鉴点

**借鉴（明确致敬的部分）**
- 三层可审计记忆 L1/L2/L3 + 每条结论可溯源
- 双循环推理：先「审题/定位薄弱点」再「求解」，不直接甩答案
- 题库 / 错题本 / 知识库 / 活书式讲解 / 掌握路径（Mastery Path）
- 沉浸式阅读 + 页码级引用

**超越（作品的差异点）**
| 维度 | DeepTutor | StudyBuddy |
|---|---|---|
| 部署 | Python + Docker + 自备 Key | **打开链接即用**，零配置 |
| 选区交互 | 有，但需自建索引 | **开箱即用的真实页面渲染 + 浮动工具条** |
| 视觉 | 默认单主题 | **四套主题即时切换**（经典白 / 深蓝科技 / 青蓝清新 / 皮卡丘黄） |
| 成本结构 | 用户自备模型 | **WorkBuddy 免密通道 + 自带 Key + 公共兜底 三通道并存** |
| 文档检索 | 多引擎 RAG（需部署） | **内置 BM25 零成本本地检索**，无需 embedding |
| 文献 | 需配 Paper Search | **内置 Semantic Scholar + OpenAlex 双源检索** |

## 五、技术架构

```
┌─────────────────────────────────────────────┐
│  React 19 + TS + Vite + Tailwind（CSS 变量驱动三主题）│
├─────────────────────────────────────────────┤
│ 视图层：Home / Chat / Reading / Library /      │
│         Knowledge / Memory / Quiz / Growth /    │
│         Research / Settings                    │
├─────────────────────────────────────────────┤
│ 能力层：pdf.js 真实渲染 + 文本层选区             │
│         mammoth(docx) · KaTeX · Mermaid        │
│         d3-force 知识图谱 · BM25 本地检索        │
│         艾宾浩斯调度 · 三层记忆                 │
├─────────────────────────────────────────────┤
│ 数据层：Dexie / IndexedDB（文档·分块·会话·消息·  │
│         知识点·图谱·题库·错题·模块·记忆·笔记）  │
├─────────────────────────────────────────────┤
│ 模型层：WorkBuddy 免密 SDK │ OpenAI 兼容流式    │
│         │ 公共兜底 Key │ 离线演示模式           │
└─────────────────────────────────────────────┘
```

**关键实现要点**
- PDF 用 pdf.js 渲染 canvas 做视觉层 + 绝对定位透明文本层做可选层，选区即得**原文 + 页码 + 前后文**
- 检索用本地 BM25（中文按字/双字切分 + 英文词元），**不需要 embedding API**，零成本零延迟
- 知识图谱用 d3-force，坐标系与容器 1:1 像素映射保证可读性
- 所有模型调用统一走 `streamLLM` 网关，通道可插拔

## 六、已知限制 & 后续路线

| 限制 | 说明 | 计划 |
|---|---|---|
| 图片 OCR | 图片资料依赖视觉模型理解，未做离线 OCR | 接入多模态模型即可（当前已支持） |
| 长文档检索 | BM25 弱于向量检索 | 后续可加可选 embedding 通道 |
| 数据同步 | 目前纯本地，换设备不同步 | 可接 WorkBuddy 云数据库做可选同步 |
| 题库难度 | 自动出题难度控制依赖模型自评 | 加入用户难度反馈闭环 |
| 移动端 | 以桌面端双栏为主 | 后续做窄屏单栏适配 |
| OAuth 回调 | WorkBuddy 账号登录只能在**已发布域名**上完成（Relay 会拒绝 localhost），本地开发需用线上地址验证 | 已按官方流程实现，线上实测可跳转到官方授权页 |

## 八、运营建议

1. **首发在 V2EX / 掘金 / 少数派发「AI 学习」话题**：这类工具天然适合截图传播，选区交互的截图很抓人。
2. **做一个「3 分钟上手」落地页**：直接内嵌选区交互 GIF，转化率比文字介绍高得多。
3. **引导用户用真实教材**：首页空态引导上传，比默认示例更有代入感；示例资料保留作为「零门槛体验」。
4. **强调隐私**：所有学习数据留在浏览器本地 —— 对「未发表论文」「内部讲义」类用户是强卖点。
5. **收集反馈**：在设置页留一个反馈入口，参赛期间的高频反馈可直接变成下一版迭代点。
